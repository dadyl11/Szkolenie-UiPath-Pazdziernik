Moduł 1 — Pliki i foldery
Zadanie 1–3 — Pliki i foldery: jeden proces z trzech workflowów
Folder: Dzien3_Zadanie1_3_Pliki_Foldery_Scalone/ · Temat: Invoke Workflow File + argumenty + Copy File / Move File + Unzip + Modify Text + Write CSV + Switch

Cel

Zbuduj jeden proces z trzech osobnych workflowów, wywoływanych kolejno z Main.xaml. Robot kopiuje pliki Excel, rozpakowuje archiwum, tworzy raport CSV z opisem rozpakowanych plików i sortuje je do folderów wg rozszerzenia. Wynik jednego workflowu jest wejściem następnego.

Pliki w folderze projektu

  • RaportFinalny.xlsx, RaportMiesieczny.xlsx — pliki do skopiowania
  • Raporty.zip — archiwum do rozpakowania i posortowania

Main.xaml

  1. Pobierz bieżący katalog projektu (Get Environment Variable, zmienna CurrentDirectory) do str_folder_projektu
  2. Użytkownik wybiera folder docelowy (Browse For Folder) — wynik do str_folder_kopii
  3. Wywołaj KopiujPliki.xaml (Invoke Workflow File) i zaloguj wynik
  4. Wywołaj RozpakujIRaport.xaml i zaloguj folder rozpakowany oraz ścieżkę raportu
  5. Wywołaj SortujPliki.xaml, przekazując mu folder rozpakowany przez RozpakujIRaport

Workflow 1 — KopiujPliki.xaml

  1. Ustaw out_bool_skopiowano_wszystko na True (Assign)
  2. Iteruj po plikach *.xlsx w in_str_folder_zrodlowy (For Each File in Folder)
  3. W pętli: zaloguj nazwę pliku (Log Message) i skopiuj plik do in_str_folder_docelowy (Copy File, Overwrite = True)
  4. Sprawdź, czy kopia istnieje (Get Local File or Folder, PathType = File, ścieżka z Path.Combine) — wynik do bool_skopiowano i do logu
  5. Zaktualizuj wynik zbiorczy: out_bool_skopiowano_wszystko AndAlso bool_skopiowano

Workflow 2 — RozpakujIRaport.xaml

  1. Ustaw out_str_sciezka_csv na Path.Combine(in_str_folder_projektu, "detale_plikow.csv")
  2. Rozpakuj Raporty.zip z folderu projektu (Extract/Unzip Files, DestinationFolder = folder projektu, ExtractToADedicatedFolder = True); folder wynikowy trafia do dirinfo_folder_rozpakowane
  3. Przypisz out_str_folder_rozpakowane = dirinfo_folder_rozpakowane.FullName
  4. Stwórz tabelę z kolumnami Nazwa pliku, Folder, Rozszerzenie, Rozmiar (Build Data Table)
  5. Iteruj po rozpakowanych plikach (For Each File in Folder):
    • Modify Text — nazwa pliku bez rozszerzenia (Find and replace: CurrentFile.Extension → pusty tekst) do str_nazwa_pliku
    • Modify Text — rozszerzenie bez kropki, wielkimi literami (Find and replace: . → pusty tekst, następnie To upper) do str_rozszerzenie
    • Add Data Row: {str_nazwa_pliku, CurrentFile.Folder, str_rozszerzenie, CurrentFile.SizeInKB.ToString}
  6. Zapisz tabelę do pliku out_str_sciezka_csv (Write CSV)
Dlaczego CSV leży w folderze projektu, a nie w rozpakowanym? Następny workflow sortuje wszystkie pliki z rozpakowanego folderu. Gdyby raport tam leżał, trafiłby do sortowania razem z resztą.

Workflow 3 — SortujPliki.xaml

  1. Stwórz tablicę nazw folderów: {"PDF", "DOCX", "XLSX"} (Assign)
  2. W pętli For Each po tablicy stwórz folder Path.Combine(in_str_folder_z_plikami, currentText) (Create Folder) i zaloguj jego nazwę (ilr_stworzony_folder.GetName)
  3. W pętli For Each File in Folder po in_str_folder_z_plikami (IncludeSubDirectories = False):
    • Switch<String> na CurrentFile.Extension.Replace(".", "").ToUpper
    • Case PDF, DOCX, XLSX → Move File do folderu o tej samej nazwie (Overwrite = True)
    • Default → Log Message poziomu Warn z nazwą pliku; plik zostaje na miejscu
  4. Zaloguj: "Pliki przeniesione"

Moduł 2 — Flowchart: Biała Lista (CEIDG)
Ćwiczenie 4 — Weryfikacja NIP na Białej Liście
Folder: Dzien3_Zadanie4_Flowchart_CEIDG/ · Temat: Flowchart + pętla + Check App State + DataTable + Write Cell

Opis zadania

  1. Sprawdź czy plik CEIDG.xlsx istnieje (File Exists)
  2. FlowDecision — plik istnieje → kontynuuj; nie → koniec
  3. Wczytaj plik do DataTable (Read Range)
  4. Otwórz stronę (https://podatki-arch.mf.gov.pl/wykaz-podatnikow-vat-wyszukiwarka/)
  5. Pętla (strzałka powrotna w Flowchart):
    • Inkrementuj licznik
    • FlowDecision — int_licznik > int_liczba_wierszy → koniec
    • Pobierz bieżący wiersz tabeli do row_wiersz_tabeli: dt_CEIDG.Rows(int_licznik - 1)
    • Wpisz NIP z tego wiersza: row_wiersz_tabeli.Item("NIP").ToString
    • Kliknij "Szukaj"
    • Check App State — sprawdź wynik weryfikacji
    • Zapisz wynik do komórki w pliku Excel (Write Cell, kolumna F, wiersz int_licznik + 1): "Figuruje na bialej liscie" albo "Nie figuruje na bialej liscie"
  6. Po pętli zamknij stronę (Use Application/Browser, CloseMode = Always)
Wskazówka: W Flowchart pętla jest bardziej widoczna niż w Sequence — strzałka powrotna do kroku z inkrementacją licznika tworzy pętlę.

Moduł 3 — Orchestrator (Assets, Queues, Dispatcher/Performer)
Zadanie 5 — Logowanie z Orchestratora
Folder: Dzien3_Zadanie5_App_Logowanie/ · Temat: Get Credential + SecureString + Pick/PickBranch

Opis zadania

Całość robisz w jednym workflowie Robotivity_App_Logowanie.xaml, który wywołujesz z Main.xaml (Invoke Workflow File, bez argumentów). W zadaniu 7 ten sam workflow dostaje argumenty, więc będzie to osobna, rozbudowana wersja pliku.

  1. Pobierz login i hasło: Get Credential → Asset: Robotivity_App_Credentials, FolderPath: Robotivity2
  2. Pobierz ścieżkę: Get Asset → Asset: Sciezka_Aplikacji, FolderPath: Robotivity2
  3. Zamknij Robotivity (Kill Process "robotivity")
  4. Otwórz Robotivity (Use Application/Browser; ścieżka do aplikacji z zmiennej str_sciezka_aplikacji)
  5. Wpisz login (Type Into → Text)
  6. Wpisz hasło (Type Into → SecureText!)
  7. Kliknij "LOG IN"
  8. Użyj aktywności Pick z dwoma PickBranch:
    • Branch 1 (Zalogowano): Trigger: Check App State na przycisk "EXIT" → Log: "Zalogowano do programu"
    • Branch 2 (Błędne hasło): Trigger: Check App State na tekst "The User name or password you enter is incorrect" → Click "OK" → Log (Warn): "Nie zalogowano do aplikacji. Sprawdz haslo"
Pick/PickBranch — aktywność "wyścigowa": pierwsza gałąź, której trigger się spełni, wygrywa. Używamy jej zamiast pojedynczego Check App State, bo mamy dwa możliwe scenariusze.
Uwaga: W Type Into dla hasła używaj właściwości SecureText (nie Text!) — hasło nigdy nie będzie widoczne w logach.

Zadanie 6 — Dispatcher
Folder: Dzien3_Zadanie6_Dispatcher/ · Temat: Bulk Add Queue Items + Add Queue Item z referencjami

Opis zadania

  1. Wczytaj Transactions.xlsx w Try Catch:
    • Try: Read Range Workbook (AddHeaders = True)
    • Catch: Kill Process "EXCEL" → Delay 2s → ponowny Read Range

Sposób 1 — Bulk Add (hurtowy, zakomentowany w projekcie):

  • Bulk Add Queue Items — QueueName: Robotivity_Bulk, FolderPath: Robotivity2

Sposób 2 — Add Queue Item z referencjami (aktywny):

  1. W pętli For Each Row:
    • Add Queue Item — QueueName: Robitivity_Single (tak, z literówką: dokładnie ta nazwa jest w projektach i w Orchestratorze), FolderPath: Robotivity2
    • Reference: CurrentRow.Item("CashIn").ToString + "_" + CurrentRow.Item("OnUsCheck").ToString
    • ItemInformation: CashIn, OnUsCheck, NotOnUsCheck
  2. Log Message: "Transakcje dodane do kolejki"
Wskazówka: Try Catch wokół Read Range — Excel może blokować plik; w Catch: Kill Process EXCEL + Delay + ponów. Bulk Add jest szybszy, ale nie pozwala nadać indywidualnych referencji.

Opcjonalne Zadanie 7 — Performer
Folder: Dzien3_Zadanie7_Performer/ · Temat: Flowchart + Queue + Robotivity + obsługa błędów

Opis zadania (Flowchart)

  1. Get Asset — pobierz Sciezka_Aplikacji z folderu Robotivity2
  2. Invoke Workflow File — Robotivity_App_Logowanie.xaml (argumenty: str_sciezka_aplikacji in, out_bool_zalogowano out). To rozbudowana wersja workflowu z zadania 5: ścieżka przychodzi z Main (nie z Get Asset wewnątrz), a workflow ustawia out_bool_zalogowano na True po udanym logowaniu i na False po błędnym haśle
  3. FlowDecision — out_bool_zalogowano?
    • False → "Koniec Pracy Robota" (If: zalogowano → log / Else → log "Nie zalogowano") + Kill Process "robotivity"
    • True → kontynuuj
  4. Pętla (strzałka powrotna):
    • Try Catch: Get Transaction Item z kolejki Robitivity_Single (FolderPath: Robotivity2)
      • Catch: qi_transaction_item = Nothing
    • FlowDecision — qi_transaction_item IsNot Nothing?
    • True → Log "Reference: " + Reference → Invoke Workflow File Procesowanie_Transakcji.xaml (argumenty: in_sciezka_aplikacji i qi_transaction_item)
    • W Procesowanie_Transakcji.xaml: wyciągnij dane z qi_transaction_item.SpecificContent, sprawdź .IsNumeric dla trzech pól; jeśli wszystkie liczbowe — Type Into + Click Accept i Set Transaction Status = Successful, w przeciwnym razie Set Transaction Status = Failed (ErrorType: Business)
Wskazówka: Logowanie i procesowanie są wydzielone do osobnych plików .xaml (reużywalność). Catch wokół Get Transaction Item ustawia qi_transaction_item = Nothing dla każdego wyjątku, więc pętla kończy się zarówno gdy kolejka jest pusta, jak i gdy pobranie elementu się nie powiedzie (np. problem z połączeniem). Złe hasło nie jest tu błędem systemowym: workflow logowania zwraca False, robot loguje "Nie zalogowano" i kończy pracę.
